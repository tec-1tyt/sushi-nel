# sushiNEL: сайт

Express-сервер віддає готовий HTML, а контент лежить у JSON. Збірка не потрібна. Усі бібліотеки й шрифти лежать у `public/`, тому сайт не залежить від CDN.

## Запуск на цьому комп'ютері

Потрібен Node.js 22.9 або новіший. Якщо `node` не знаходиться, відкрий новий термінал: після встановлення шлях оновлюється лише в нових вікнах.

```bash
npm install
```

```bash
npm run dev
```

Адреси: `http://localhost:3000/` (чеська), `/uk/`, `/en/`.

Без налаштувань заявки просто друкуються в термінал, це зручно для перевірки. Щоб вони приходили тобі, скопіюй `.env.example` у `.env` і заповни `TELEGRAM_BOT_TOKEN` та `TELEGRAM_CHAT_ID` (або SMTP).

## Як міняти контент без коду

Усе в папці `data/`. Після збереження сервер сам перечитує файли. Якщо в JSON помилка, сайт лишається на попередній робочій версії, а причина з'являється в лозі. Перевірити файли можна так:

```bash
npm run check:data
```

### Ціни й страви: `data/menu.json`

- `price`: ціна в кронах. Для страв із розмірами замість неї є `variants`, і в кожного варіанта своя `price`.
- `available: false`: страва зникає з сайту, а її замовлення сервер не прийме.
- `name`, `desc`: текст трьома мовами (`cs`, `uk`, `en`).
- `weight` (`"300 g"`), `pieces` (`32`), `volume` (`"500 ml"`): розмір порції. Якщо поле порожнє, на картці його просто немає.
- `allergens`: коди `gluten, crustaceans, eggs, fish, soybeans, milk, nuts, sesame, molluscs, sulphites, lupin, alcohol`. Фільтр «Без:» працює саме за ними.
- `badge: "new"`: мітка «Novinka». `alcohol: true`: мітка 18+ і підтвердження віку в кошику.
- `id` не міняй: на нього спираються фото й кошик. Нова страва отримує новий унікальний `id`.

Фото нової страви:

```bash
python tools/prepare_images.py dish шлях/до/фото.jpg id-страви
```

Скрипт сам вирізає білий або чорний фон і стискає файл. Страва без фото теж показується, просто без картинки.

### Акції: `data/promotions.json`

- `active: true`: акція видна на сайті.
- `validFrom`, `validTo` (`"2026-12-31"`): необов'язкові дати. Після `validTo` акція зникає сама.
- `threshold`, `gift`: сума й `id` страви-подарунка. За ними працює смужка прогресу в кошику, а в заявці з'являється рядок «Dárek».
- `terms`: умови акції.

### Контакти, години, доставка: `data/site.json`

`null` означає, що даних немає. Поки в `.env` стоїть `SHOW_PLACEHOLDERS=true`, на сайті видно мітку `[doplnit]`. Заповни поле, і мітка зникне. Якщо поставити `false`, порожні місця просто не показуються.

Наприклад, зони доставки:

```json
"zones": { "cs": "Chomutov a Jirkov", "uk": "Хомутов і Їрков", "en": "Chomutov and Jirkov" }
```

Посилання на Wolt, Bolt, Foodora чи Telegram з'являться самі, щойно їх вписати в `ordering` або `socials`.

### Тексти інтерфейсу: `data/i18n.json`

Заголовки, кнопки, помилки форм, усе трьома мовами.

## Деплой

Підійде будь-який хостинг із Node.js (VPS, Railway, Render, Fly). Сервер має працювати постійно, бо ліміти запитів зберігаються в пам'яті процесу.

1. Заповни `.env`: `NODE_ENV=production`, `SITE_URL`, `CSRF_SECRET`, Telegram або SMTP.
2. Якщо перед застосунком стоїть Nginx або Cloudflare, задай `TRUST_PROXY=1`. Інакше ліміти рахуватимуться за адресою проксі.
3. Запусти `npm ci --omit=dev`, потім `npm start`.
4. Перевір `/healthz`: там має бути `"notify": true`.

У production без `CSRF_SECRET` сервер не стартує. Без Telegram і SMTP він працює, але чесно відмовляє у формах і просить подзвонити, щоб жодне замовлення не загубилося мовчки.

## Демо на GitHub Pages

Статична копія для показу живе на гілці `gh-pages`: https://tec-1tyt.github.io/sushi-nel/

GitHub Pages не запускає сервер, тому там форми не надсилають заявки, а просять подзвонити. Для справжніх замовлень потрібен хостинг із Node.js (розділ вище). Зібрати копію заново:

```bash
npm run build:static
```

## Безпека

- **Форми:** валідація через zod, ціни рахує лише сервер, honeypot, ліміт запитів, підписаний CSRF-токен, перевірка Origin, опційно Cloudflare Turnstile.
- **Заявки:** йдуть як чистий текст, без розмітки, тому HTML у полі форми нічого не зробить.
- **Заголовки:** helmet, CSP без `unsafe-inline`, HSTS у production, Referrer-Policy, X-Content-Type-Options.
- **База даних:** її немає, тому немає й ґрунту для SQL/NoSQL-ін'єкцій.
- **Персональні дані:** на сервері не зберігаються, у логи не пишуться.

Тести запускає ця команда:

```bash
npm test
```

## Структура

```
server/render/   шаблони сторінок, SEO, іконки, гілки сакури
public/          CSS, JS, шрифти, фото, бібліотеки
tools/           підготовка фото, шрифтів, бібліотек
tests/           тести бекенду
```

Список того, що ще треба уточнити, лежить у `DATA_REVIEW.md`.
